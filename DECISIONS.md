## Session Decisions
- [BOOT/PARSE] Decision: Convert constructor-based constants in `main.gd` to runtime vars for compatibility (`PackedStringArray(...)`, `Color(...)`). | Why: current parser raised constant-expression errors. | Alternative: keep constants and require a different Godot parser/runtime behavior.
- [ASTEROIDS] Decision: Define `variant` in `AsteroidSystem.update_asteroids()` from asteroid payload before use. | Why: code referenced `variant` before declaration, causing parse/runtime failure. | Alternative: inline repeated dictionary lookups at each branch.

- [ATTACK_PLAN] Decision: Resolve duplicated root `ATTACK_PLAN.md` sections into a single canonical structure. | Why: file had contradictory duplicate blocks from prior sessions; a single source reduces ambiguity for queued runs. | Alternative: keep both blocks and infer latest state heuristically each session.
- [CAMERA D.5] Decision: Mirror web `updateCamera` movement constants in Godot (`speed=38`, y clamp `6..140`, x/z clamp `±170`). | Why: current Godot camera movement was slower and more constrained than web source-of-truth values. | Alternative: keep current Godot tuning and treat camera handling as an approved difference.
- [CAMERA D.5] Decision: Clamp per-frame mouse look deltas to `±220` before applying sensitivity. | Why: web clamps pointer deltas to avoid focus/pointer-lock jump spikes; Godot behavior should match for camera stability. | Alternative: leave unclamped and rely on platform input smoothness.
- [CAMERA D.5] Decision: Align CameraSystem startup/reset pose to web (`camPos(0,55,70)`, `yaw=PI`, `pitch=-0.65`). | Why: Godot defaults were materially different and changed initial framing/orientation vs source-of-truth behavior. | Alternative: keep existing Godot defaults as a prototype-specific camera framing.
- [POINTER D.2] Decision: Gate PLAYING camera look and play-click actions on active mouse capture, and consume first click after focus-out as recapture-only. | Why: web behavior relocks before gameplay actions; without gating, Godot can process unintended build/sell/look on relock transitions. | Alternative: always process clicks/looks immediately after focus return.
- [MENU D.3] Decision: Make menu virtual-cursor hit testing iterate controls in reverse (top-most first) and skip disabled/invisible buttons. | Why: web `pickMenuHitTarget` effectively clicks the top-most eligible element under cursor; forward-order scan could select non-topmost or disabled targets. | Alternative: preserve fixed-order scan and allow disabled/highly obscured controls to be highlighted.
- [MENU D.3] Decision: Set Godot menu virtual-cursor clamp margin to `14` to match web `MENU_CURSOR_MARGIN`. | Why: previous Godot margin (`8`) allowed cursor positions web UI never permits, creating subtle menu navigation drift near edges. | Alternative: keep smaller Godot-specific margin for looser movement.
- [ASTEROIDS F.7] Decision: Feed seeker asteroids a live target-point list and retarget them to the closest structure each update. | Why: web seekers explicitly steer toward closest live building instead of flying only on initial centerline direction. | Alternative: keep seeker trajectory as command-center-only vector for simpler movement.
- [ASTEROIDS F.6/F.7] Decision: Move spawner meteor cadence from fixed reset (`6.0s`) to web-scaled cooldown (`max(2.2, 5.2 - adj*0.12)`). | Why: web spawner pressure ramps with wave scaling; fixed cooldown under-represents late-wave threat behavior. | Alternative: preserve fixed interval for simpler tuning.
- [ASTEROIDS F.8] Decision: Trigger asteroid impacts via near-target threshold (`2.2`) / low altitude check instead of using `impact_radius` as trigger distance. | Why: web uses a fixed impact trigger and applies `impactRadius` only for resulting AOE damage; using radius as trigger detonates too early for large-radius variants. | Alternative: continue radius-based trigger for simpler single-value behavior.
- [ASTEROIDS F.6] Decision: Replace placeholder variant picker with web-style wave-ramped variant weights and capped active-type pool (`2 + floor(wave/3)`, always including `normal`). | Why: uniform/random placeholder selection did not match web pacing or composition pressure over waves. | Alternative: keep simplified random variant selection for prototype readability.
- [ASTEROIDS F.6] Decision: Set `colossus` visual size multiplier to `10.0` to match web spawn sizing. | Why: lower Godot value significantly underrepresented colossus screen presence and perceived threat. | Alternative: keep reduced size as a prototype readability compromise.
- [ASTEROIDS F.7] Decision: Assign seeker target at spawn to the closest live structure, not just during subsequent movement ticks. | Why: web seeker spawn logic chooses nearest building immediately, so first-frame heading should already reflect target acquisition. | Alternative: rely only on per-frame retargeting after spawn.
- [ASTEROIDS F.6/F.9] Decision: Add run-scoped asteroid discovery tracking with a 5-second HUD notice and audio event on first sight of each variant. | Why: web tracks discovered variants and surfaces discovery feedback; without this, new variant introductions are silent and less readable. | Alternative: keep discovery implicit with no explicit notification system.
- [ASTEROIDS F.6] Decision: Add discovery-aware variant pool construction (known-first + keep `normal` + optional unknown intro from wave 2). | Why: web uses discovered history to shape each wave’s variant pool, not just raw global weighting. | Alternative: continue using only weighted global pool independent of discovery state.
- [ASTEROIDS F.6] Decision: Cache and reuse a single variant pool per wave, rebuilding only when wave index changes. | Why: web configures `waveVariantPool` at wave start; per-spawn pool recompute can shift composition mid-wave in ways web does not. | Alternative: continue recomputing variant pool every spawn using latest discovery set.
- [ASTEROIDS F.9] Decision: Map discovered variant ids to user-facing names in HUD discovery text. | Why: web discovery toast presents readable variant names; raw ids are less legible and less parity-aligned for UX. | Alternative: show raw id strings directly.
- [ASTEROIDS F.9] Decision: Include discovery description text in HUD notice alongside variant name. | Why: web discovery payload includes `name` + `description`; name-only notice drops useful context when new variants appear. | Alternative: keep compact name-only discovery notice.
- [ASTEROIDS F.7] Decision: Apply `stasisTimer` and `pulsarSlowTimer` movement effects in `update_asteroids` (`freeze` and `0.52` speed multiplier). | Why: web movement loop applies these timers directly; ignoring them blocks parity for Nova slow/stasis interactions. | Alternative: postpone timer handling until full status-effect feature pass.
- [ASTEROIDS F.7] Decision: Decay `radarMarkTimer` in asteroid update loop alongside other status timers. | Why: web decrements this timer continuously; leaving it static breaks duration semantics for mark-dependent effects. | Alternative: handle radar mark decay in a separate subsystem later.
- [ASTEROIDS F.7/F.8] Decision: Use planar XZ distance (not full 3D) for seeker nearest-target selection, impact trigger proximity, and asteroid death AOE/EMP range checks. | Why: web source uses `Math.hypot(x,z)` grid distance for these behaviors; including Y introduced false range differences due to height offsets. | Alternative: keep 3D distance checks and tolerate altitude-influenced behavior drift.
- [ASTEROIDS F.7/F.8] Decision: Drive non-seeker asteroid movement/impact off each asteroid's `target` point and center impact AOE/EMP on that point for impact deaths. | Why: web asteroids carry a per-spawn target and detonate relative to that target; command-center-only targeting compressed impact distribution and altered defense interaction patterns. | Alternative: keep command-center-anchored movement/impact for all non-seekers.
- [ASTEROIDS F.6/F.7] Decision: Generate randomized non-seeker target points in web board range (`[-40, 40]` X/Z) and pass parent target into spawned meteors/splitter children. | Why: web non-seekers aim at varied grid coordinates and child/spawner asteroids keep the parent impact lane; recomputing fresh targets changed lane continuity and spread. | Alternative: keep command-center/random recompute targeting per child spawn.
- [ASTEROIDS F.6/F.7] Decision: Match base asteroid spawn geometry to web radial spawn (`r=160..220`, `y=90..120`) instead of low side-edge spawn. | Why: web spawn lane and time-to-impact depend on high-altitude radial entry; edge-at-ground spawning compresses travel time and changes early-wave pressure. | Alternative: keep side-edge low spawn for simpler arena-local behavior.
- [ASTEROIDS F.6/F.7] Decision: Spawn spawner-created meteors with web-like child derivation from parent stats (`speed=max(26,parent*1.45)`, `hp=max(45,parentMaxHp*0.42)`, `impactDamage=parent*0.8`, `impactRadius=0.95`) and close local offset. | Why: generic meteor spawn kinematics over/under-shot child threat relative to web spawner behavior and broke expected burst profile. | Alternative: keep generic `_spawn_asteroid_at("meteor")` stats for simplicity.
- [ASTEROIDS F.6/F.7] Decision: Spawn splitter children using web side-based local offsets (`(-0.55,0.2,-0.25)` / `(0.55,0.2,0.25)` pattern) instead of wide random offsets. | Why: web splitter behavior creates a readable left/right split lane; broad random offsets changed immediate child clustering and visual trajectory consistency. | Alternative: keep random child offsets for variation.
- [ASTEROIDS F.6/F.7] Decision: Apply web-like splitter lane divergence by rotating child heading relative to parent lane (`±0.35` / `±0.42` by split level) and deriving child target from that rotated direction. | Why: web splitter children diverge by yaw from parent velocity; shared parent target caused both children to collapse back into the same lane. | Alternative: keep identical inherited target for both children.
- [AUDIO K.2] Decision: Extend `AudioService` optional event map to include web event ids `upgrade_refund` and `shield_hit`. | Why: web emits these event types; silently dropping them in Godot makes future parity callsites no-op even when SFX assets exist. | Alternative: keep only currently-used event ids and add others later ad hoc.
- [AUDIO K.2] Decision: Emit `asteroid_destroyed` reason-based audio from `_remove_asteroid` (centralized), not projectile kill callsites. | Why: web resolves destroy audio in a single death handler by reason (`combat`/`shield` vs `impact`); centralization prevents callsite drift and missing sound when new kill paths are added. | Alternative: keep per-caller emission and manually duplicate reason logic.
- [AUDIO K.2] Decision: Mirror web `gameAudioEngine` semantics for `asteroid_destroyed`/`shield_hit`: destroy SFX only for `reason=="combat"` and throttle `shield_hit` to 72ms minimum interval. | Why: web explicitly suppresses shield-destroy destroy SFX and rate-limits shield-hit spam; unconditional playback overstates shield interactions. | Alternative: keep generic per-event playback with no cooldown.
- [AUDIO K.2] Decision: Keep `wave_start` / `wave_cleared` audio events silent by removing optional SFX mapping in Godot. | Why: web event handler explicitly treats these as no-op markers; playing SFX on wave edges introduces non-parity sound cues. | Alternative: keep whoosh/door optional mapping for added feedback.
- [AUDIO K.2] Decision: Use a dedicated short-lived player for `build_sell` and stop playback at ~72ms to mirror web clip behavior. | Why: web explicitly truncates door-close playback for sells; full-length playback in Godot overemphasized sell actions and diverged from source cadence. | Alternative: play full `build_sell` clip via shared SFX player.
- [ASTEROIDS F.6] Decision: Remove spawner meteor spawn-on-death from `on_asteroid_destroyed`; keep spawner behavior limited to periodic spawn while alive. | Why: web `handleAsteroidDeath` does not create extra meteor on spawner death; retaining it inflated post-kill pressure beyond source behavior. | Alternative: keep death spawn as a Godot-only difficulty modifier.
- [ASTEROIDS F.6] Decision: Remove colossus death AOE from `on_asteroid_destroyed`; keep colossus threat in spawn stats/impact only. | Why: web death handler has no special colossus death blast; Godot-only death AOE added non-source damage spikes when large enemies die. | Alternative: preserve colossus death blast as custom Godot difficulty flavor.
- [ASTEROIDS F.6 / ECON H.4] Decision: Replace EMP death turret-disable effect with web-style power drain (`radius=18`, `22 * POWER_DRAIN_GLOBAL_MUL` per building hit, including command center). | Why: web EMP death path drains stored power by nearby-building count and does not apply turret disable timers; disable behavior skewed defense uptime. | Alternative: keep turret-disable EMP as a simplified crowd-control proxy.
- [UPGRADES I.2] Decision: Implement same-inactive-phase upgrade refund for prototype slots by re-pressing the same upgrade key, including current-phase prereq invalidation cleanup. | Why: web exposes refundable upgrades during inactive phase and auto-refunds now-invalid current-phase dependents; buy-only flow diverged from phase/refund semantics. | Alternative: postpone refunds until full upgrade tree UI exists.
- [UPGRADES I.2 / UI J.3] Decision: Mark owned research labels with `[R]` when refundable in current inactive phase and not in wave combat. | Why: web state exposes `refundableUpgradeIds`; without a marker, same-key refund capability is hidden/discoverability is poor. | Alternative: keep refund available but undocumented in label text.
- [VALIDATION] Decision: Continue logging headless parse check as blocked in automation while still running available lint/static checks. | Why: `godot --headless --check-only` cannot execute in this terminal context. | Alternative: skip all validation steps until CLI path is fixed.
